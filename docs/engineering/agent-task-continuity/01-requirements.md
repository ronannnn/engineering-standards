# 需求分析：任务持续执行补充

## 背景与目标

### 问题

现有标准有交接和续做记录，但对追问归属、授权范围、人工暂停及运行等待原因说明不足。

### 目标

补充通用协作规则及模板填写位置，保持八阶段、固定锚点与旧门禁兼容。

### 非目标

不开发运行平台，不接入 GitHub 或飞书，不增加强制字段门禁。

## 现有系统分析

复用 policies/lifecycle.md 的交接与恢复规则、04/05 模板及阶段技能；项目环境由 project-context.md 声明。现有 Python 门禁检查产物与依赖，不验证真实执行权限；本次不扩大其职责。

## 术语

任务身份为运行目录、模块路径（无模块写根）和任务编号。运行状态表示正在做或在等什么，与产物冻结状态和八阶段分别记录。

## 功能需求

### FR-1 补充持续协作方法

- 描述：明确任务归属、授权、暂停恢复、运行状态和通知方法，同步模板技能与来源。
- 优先级：必须
- 场景：
  - Given：开发中收到补充说明、用户暂停或中断。
  - When：继续处理或换执行者接手。
  - Then：找到原任务、核对授权及停止条件，再按已有阶段推进，不重复派发或伪造完成。

## 非功能需求

新增运行时依赖为 0；原有模板二级锚点不改名；旧样例和模块样例门禁均通过。

## 验收标准

| 编号 | 对应需求 | 判定方式 | 可自动化 |
|---|---|---|---|
| AC-1 | FR-1 | 走查追问、授权、暂停、状态及恢复例子，检查模板技能入口与来源 | 否 |
| AC-2 | FR-1 | 全部单元测试及两份样例全链校验通过 | 是 |

## 范围外

运行调度器、消息发送、真实权限隔离、自动合并和生产部署。

## 依赖与假设

参考 dsh-superagent-prototype 官方资料，中文重述；复用当前仓库的批量执行授权和自动阶段规则。

## 风险与开放问题

无未决问题：本次仅补文档与模板，不改变门禁判据；执行约定不能宣称已由程序强制。
