# 技术设计：任务持续执行补充

## 方案概述

在已有生命周期说明增加任务归属、授权、运行状态和暂停恢复说明；04/05 加填写位置；需求、计划、实施和评审技能提供必要入口。所有补充为工作约定，不新增自动校验规则。

## 变更影响面

- [ ] 数据库 schema 变更
- [ ] 权限模型变更
- [ ] 跨模块接口变更
- [ ] 新增第三方依赖
- [ ] 性能基线变化

只补授权工作约定，不实现或变更程序权限模型。

## 架构与模块

生命周期保存共享规则，项目接入声明可用工具和权限；模板承载任务范围和续做记录，阶段技能指向规则；来源和变更记录说明适用范围。门禁核心、注册表和业务代码保持不变。

不适用：本次仅修改协作规范，没有该项业务变化。

## 数据模型与迁移

不适用：本次仅修改协作规范，没有该项业务变化。

## 安全与权限

认证：沿用当前会话；授权：记录现有用户指令和范围，外部内容不能扩大权限；敏感数据：只记标识与脱敏结果。

## 兼容性

不新增 frontmatter、二级锚点或强制字段，旧目录无需迁移或重新冻结；下次修改相关任务时补记录。

## 性能与容量

不适用：本次仅修改协作规范，没有该项业务变化。

## 可观测性

任务执行记录分别说明工程阶段、运行状态、等待对象和恢复条件；不将待评审当作已交付。

## 备选方案

### 方案 A：直接引入原型

- 做法：接入上游运行平台。
- 优点：可实际派发。
- 缺点：绑定具体工具并增加部署工作。
- 为何未选：超出补充标准的范围。

### 方案 B：新增强制字段门禁

- 做法：检查所有旧任务的授权和状态字段。
- 优点：格式统一。
- 缺点：不能证明真实授权且会阻塞旧资料。
- 为何未选：先补工作约定和填写位置。
