# 需求：让 Agent 从需求到交付、维护的流程可靠且可持续

## 背景与目标

### 问题

本仓库用于让分工明确的 Agent 完成需求、设计、开发、交付和长期维护。只读评审发现八处可复现的问题：合并前要求完成上线后复盘；RED 证据串读 GREEN 内容；验收矩阵未关联实际用例；工程检查失败仍可交付；单独校验 07 未要求评审报告冻结；错误 frontmatter 导致异常退出；CI 把角色配置目录当需求目录；`--next` 仅凭状态文字判断完成。

现有流程还缺少统一的任务交接、换会话续做、紧急修复和维护任务回流方法。用户已要求学习相关开源项目及社区实践，并授权开始修改；本文件用于明确本次修改范围，不代替人的签收。

### 目标

- 八处已确认问题都有回归测试，违规样本会被拦住，合法样本能通过。
- 合并前校验覆盖 01–07；交付后再完成 08；完整归档仍校验九份产物。
- Agent 能根据明确的交接信息接手任务，在中断后核实进度和已执行操作，再继续工作。
- 小改动、常规开发、紧急修复有明确的执行说明；保留八阶段结构和必要的人工签收。
- 项目自行选择开发语言、框架、设计系统、验证命令和部署环境。
- 提供三类真实试跑场景，用于后续验证这套标准是否减少遗漏、返工和重复执行。

### 非目标

不开发新的 Agent 运行平台，不接入具体模型 API，不部署生产服务，不自动发消息，不引入特定语言或视觉风格作为统一要求，不复制上游技能正文。角色职责不要求每个角色都对应一个并行进程。

## 现有系统分析

`AGENTS.md` 规定八阶段和九份冻结产物；`templates/` 定义结构；`skills/` 定义阶段与角色行为；`gates/spec.py` 注册流程；`gates/run.py` 调度校验；`gates/_lib.py` 解析产物。现有 17 项自测以 `examples/sample-run/` 为基线，修改前已全部通过，但没有覆盖上述八处问题。

复用现有 frontmatter、中文标题锚点、门禁公共库、样例和临时目录测试方式。冲突主要在：PR 全链校验要求上线后的复盘提前完成；07 依赖链只登记测试报告；证据和验收关联检查不足；技能中的小改动说明存在直接跳到 04 的表述，与八阶段规则不一致。脚手架会预置九份草稿，本次沿用它创建运行目录。

## 术语

- 合并前校验：检查进入合并与交付所需的 01–07，不要求提前完成上线后的复盘。
- 完整归档校验：检查九份产物和整个依赖链。
- 交接信息：任务目标、范围、输入、交付物、验收方法和接收角色。
- 续做记录：已完成事项、未完成事项、最近验证、下一步，以及有无执行结果尚未核实的外部操作。
- 紧急修复：用户受到显著线上影响时优先恢复服务的最小改动，事后仍需补齐深入评审与复盘。

## 功能需求

### FR-1 修复门禁的漏检和异常退出

- 描述：准确检查证据、验收用例、工程检查和交付前置条件；无效输入输出可定位的问题；下一步判断不能将无效冻结视为完成。
- 优先级：必须
- 场景：
  - Given：样例已通过，且另有删除 RED 内容、删除被引用用例、工程检查失败、评审未冻结或签收缺失的变体。
  - When：运行相应的单阶段、全链或下一步检查。
  - Then：合法样例返回成功，违规变体返回失败并指出原因，格式错误不产生未捕获的 traceback。

### FR-2 让交付和上线后复盘按正确顺序执行

- 描述：明确合并前与完整归档的校验范围；CI 只识别需求运行目录，忽略索引和项目配置；全链检查保留归档用途。
- 优先级：必须
- 场景：
  - Given：01–07 已有效冻结且 08 仍为草稿，或者本次仅修改 `_custom/roles/` 中的配置。
  - When：运行合并前检查或 CI 的目录选择逻辑。
  - Then：前者不被 08 草稿阻塞，后者不会被当成缺少九份产物的需求；完整归档检查仍拒绝未完成的 08。

### FR-3 保持项目选择并按改动大小安排工作

- 描述：通用规则只约定职责、产物和验证要求；语言、框架、设计系统和具体命令由项目声明。小改动减少重复描述，复杂改动保留完整分析，阶段不静默跳过。
- 优先级：必须
- 场景：
  - Given：一个纯后端项目和一个有界面的项目分别接入标准。
  - When：准备项目说明和需求执行路径。
  - Then：二者都能填写自己的技术与验证信息；无界面的 03 说明理由后按规则签收，界面项目记录自身设计系统与实际页面检查方式。

### FR-4 明确角色交接、独立评审和中断续做

- 描述：执行者拿到完整交接信息；评审区分阻塞问题与改进建议，依据真实变更及验证；中断后先核对仓库和外部执行结果，避免重复发布、迁移或写入。
- 优先级：必须
- 场景：
  - Given：开发任务进行一半后换会话，或者发布命令返回结果前断线。
  - When：新的执行者接手。
  - Then：能找到任务目标、范围、证据、未完成项和下一步；外部结果未确认时先核实，不直接重复执行；评审分歧有裁定和后续处理记录。

### FR-5 补齐持续维护和紧急修复的处理方法

- 描述：交付时明确维护责任、观察项、告警入口、回滚依据和后续任务；故障处理明确协调、修复和记录职责，可由同一人兼任。紧急修复保留最小验证和人的决策，恢复后安排补充评审和改进任务。
- 优先级：必须
- 场景：
  - Given：已上线功能出现故障、漏洞或需要依赖升级。
  - When：维护负责人按标准接手。
  - Then：能确定处理责任和恢复验证方法，将修复或改进作为可跟踪的新任务，并把复盘行动关联到负责人和期限。

### FR-6 提供标准本身的试跑与迁移说明

- 描述：提供小功能、旧问题修复、模拟故障三类试跑场景及记录方式；区分门禁脚本测试与真实 Agent 试跑；记录新旧规则差异及存量产物补充方式。
- 优先级：必须
- 场景：
  - Given：团队准备采用新版本，或者要比较修改前后的标准。
  - When：阅读迁移说明并执行试跑。
  - Then：知道旧产物如何补齐，有明确成功判据，可记录完成情况、返工、耗时和重复操作；未执行的试跑明确标记为未执行。

## 非功能需求

- `gates/` 继续仅使用 Python 3 标准库，新增第三方运行依赖数为 0。
- 必须运行 `python3 -m unittest discover gates/tests`，既有 17 项用例不得无理由删除或放宽；新增回归覆盖八处已确认问题的正常和异常路径。
- 门禁失败输出 `文件名:行号: 原因`，错误 frontmatter 不输出未捕获异常。
- 新增或收紧的门禁判据同步更新模板、对应阶段技能、样例和 `CHANGELOG.md`；不以文档关键词数量代替实际工作质量。
- 不伪造人的签收、测试执行或真实 Agent 试跑结果。

## 范围外

生产监控系统建设、自动值班平台、模型选型与费用集成、强制多 Agent 并行运行、真实业务项目交付均不在本次范围；本次为这些工作提供通用操作规则及记录方式。

## 依赖与假设

依赖仓库维护者签收本次需求。后续技术设计若不触发已有重大设计条件，可由机器门禁冻结；03 无用户界面改动，需按现有整份不适用规则确认。07 仍由人签收。任何改变这三个签收边界的决定都需要显式授权。

研究依据来自本聊天已经读取的 DeepSeek Harness、Superpowers、BMAD Method、Vercel Agent Skills、Impeccable、Anthropic、OpenSpec、GitHub Spec Kit、Google Engineering Practices、PagerDuty、LangGraph 和 Agent Skills 官方资料。采用中文重述；最终来源登记核对所引用具体版本与文件，不把上游示例直接视为生产实现。
