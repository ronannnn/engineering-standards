# 需求：支持模块与多层子模块的完整工程资料

## 背景与目标

### 问题

当前根目录固定九份产物，只识别根需求及验收；文件夹拆分后子需求、模块依赖、设计、任务与证据均不会被递归校验。

### 目标

可按功能模块和多层子模块组织 01–06 与 08，公共架构和规范在根目录，07 统一交付；引用可追溯、校验覆盖完整、旧单目录无需迁移。

### 非目标

不限定语言或设计系统，不新增外部依赖，不引入工作流服务，不复制上游正文，不把文件夹层次等同于业务依赖。

## 现有系统分析

复用 gates/spec.py 注册、run.py 的依赖闭包与阶段检查、_lib.py 的产物解析、各阶段校验器和现有 51 项测试。新增模块清单和树协调层，复用局部校验，不重写阶段规则；CI 已把深层路径映射到根运行目录，可增加模块样例验证。脚手架目前只创建根产物，需要模块初始化工具。

## 术语

模块路径为运行目录 modules/ 下的稳定相对路径；全限定引用例如 orders/refund#AC-1，本地编号仍用 AC-1。模块清单描述本次变更的模块，不要求列出整个项目所有模块。

## 功能需求

### FR-1 多层目录及兼容性

- 描述：显式清单列出模块和子模块，提供初始化和索引；无清单仍走原九份文件流程。
- 优先级：必须
- Given：旧样例或带 user/access 等模块路径的新运行目录。
- When：初始化并运行阶段检查。
- Then：旧用法不变，多层模块产物被读取并能在错误中定位路径，未登记产物不会被静默忽略。

### FR-2 各阶段对应和依赖

- 描述：模块 01–06 与 08 使用同一模块路径，依赖局部上一阶段与根公共基线；声明模块依赖并拒绝循环、失效公共修订及越界路径。
- 优先级：必须
- Given：两个模块或一个子模块引用其他模块。
- When：推进阶段或更新公共文档修订。
- Then：未冻结的前置模块和过期公共基线会阻塞推进；可选择模块及依赖执行局部检查。

### FR-3 可追溯验收与统一交付

- 描述：命名空间隔离编号，根计划和测试汇总模块 AC，复用模块测试记录并保留跨模块集成验证；根 07 汇总模块测试与评审修订，模块 08 依赖统一交付。
- 优先级：必须
- Given：模块内部都用 AC-1/T-1 等局部编号。
- When：根计划、测试、交付或归档检查。
- Then：限定引用准确关联所属模块；漏验收、假用例、未冻结模块、发布修订失配或缺模块复盘会被拦截。

### FR-4 文档与来源同步

- 描述：同步所有阶段模板、角色和技能、入口、CI、迁移说明及至少一个多层样例，记录研究来源和实际执行边界。
- 优先级：必须
- Given：维护者采用新组织方法。
- When：按说明创建需求并检查。
- Then：公共资料不用复制，后续阶段知道如何引用模块，测试与样例可复现。

## 非功能需求

仅 Python 3 标准库；已有 51 项测试保持通过。路径和 JSON 错误输出定位，不能执行文档内容；根未变化的九份产物格式保持兼容。
