# 怎样向 Agent 发起工作

日常优先使用自然语言。Agent 识别意图、定位需求、核对产物和暂停记录，再按阶段读技能；不要求用户记住阶段编号或角色名。首次接入按 [SETUP](../SETUP.md) 完成。

## 自然语言、技能和脚本的分工

| 入口 | 用途 | 边界 |
|---|---|---|
| 自然语言 | 表达目标、补充信息、询问和调整工作 | 结合上下文判断，不因模糊说法扩大范围 |
| 技能或可选快捷指令 | 帮助 Agent 选用阶段方法 | 取决于工具实际安装和支持，不是强制执行器 |
| 程序命令 | 实际创建产物、检查结构和依赖 | 成功只证明对应检查通过，不证明真实审批或执行发生 |

可以说“使用 org-requirements 技能”，也可以说“开始这个需求”。没有注册的聊天指令不能写成已可用功能；普通自然语言不依赖斜杠命令。

## 常见说法如何处理

| 用户说 | Agent 应做 |
|---|---|
| 把标准接入当前项目 | 读取 GitHub SETUP，从同仓库获取标准，检查项目并按授权接入验证 |
| 开始优惠券导入需求 | 分析代码与项目配置，选 slug，初始化目录，从 01 写需求和验收标准 |
| 继续 coupon-import | 读取产物、续做和暂停记录，核对修订、工作区及外部回执，检查下一阶段后继续 |
| 退款还要支持部分退款 | 交回原负责人判断，改变冻结范围先修订上游，不重复开工 |
| 看看做到哪了 | 简报工程阶段、运行状态、证据和未完成项；询问进度不解除暂停 |
| 检查能否交付 | 运行 01–07 检查，列出缺口，不替人签收或自动部署 |
| 先别改，只看问题 | 保留暂停范围，做获准的检查和说明，不修改代码或冻结产物 |
| 更新项目使用的标准 | 对照来源和迁移说明，按 SETUP 保留项目定制与历史 |

需求不明确时先查索引、最近续做记录和当前会话。能唯一确定就继续；多个需求可能匹配时，只问清处理哪一个，避免写错目录。

## 实际命令

现有入口为 `scripts/init-docs.sh`、`scripts/init-module.py` 和 `gates/run.py` 等仓库脚本。业务项目调用时使用实际标准路径，快照示例见 [README](../README.md)。`--next` 只校验并提示下一阶段，不执行开发；`--stage` 自检通过不等于已冻结。

快捷指令按工具需要配置为同一方法的别名，不另建产物契约，不绕过暂停、授权、冻结与签收。即使指令叫“交付”，也需实际校验和签收。发布、对外消息与自动合并遵循项目授权。

## 报告结果

说明改了什么、实际跑了什么、还缺什么和下一步。需要决定或补信息时提出具体问题，已有授权内持续推进。技术与设计约束来自项目配置，交接、恢复和维护按 [生命周期](lifecycle.md) 执行。
