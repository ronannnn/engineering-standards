# 安全

安全不是上线前的一次扫描，而是设计与实现阶段必须落地的约束。本文规定各阶段的最低要求。

## 02 技术设计：必须回答的三个问题

- **认证**：谁以什么身份进入？token 从哪来、如何校验、过期与刷新怎么处理。
- **授权**：谁能对什么资源做什么动作？判定点在哪一层？越权返回什么、如何审计？
- **敏感数据**：采集哪些、传输是否加密、存储是否加密、日志与导出是否脱敏。

三项任一未写，`gates/gate02_design.py` 直接判失败。

## 05 编码实现：必须做到的六件事

1. **参数化查询**：SQL 与命令一律用参数，不做字符串拼接；动态表名、列名走白名单。
2. **输出转义**：HTML、CSV、日志分别用对应转义；禁止把用户输入直接拼进模板。
3. **最小权限**：新接口默认需要权限点，不允许「先不加权限后面再说」。
4. **输入校验**：类型、长度、范围、文件类型与大小在入口处校验；非法输入返回明确错误，不回显内部细节。
5. **日志脱敏**：不记录 token、密码、身份证、银行卡、完整 CSV/请求体。
6. **依赖审查**：新增第三方依赖必须评估维护状态、许可证、已知漏洞；能在可用维护的依赖里解决，就不要手写。

## 06 测试与评审：必须验证的场景

| 场景 | 验证方式 | 不合格表现 |
|---|---|---|
| 未登录访问 | 断言 401 | 返回 200 或 500 |
| 越权访问（横向/纵向） | 用他人身份或低权限身份断言 403 | 只测了有权限的路径 |
| 注入 | 带 `' or 1=1 --` 的入参与文件内容 | 只测正常输入 |
| 敏感信息泄漏 | 扫描响应体与日志 | 报告里只写「未发现问题」 |
| 文件上传 | 类型、大小、超大行数、编码 | 只测正常 CSV |
| 迁移回滚 | 预发执行迁移与回滚各一次 | 只验证了正向迁移 |

评审报告必须覆盖「注入」与「越权」两项，`gates/gate06_review_report.py` 会检查。

## 风险升级

以下情况必须停下找人，不得自行放行：

- 涉及资金、支付、提现、额度调整的改动。
- 涉及删除、批量修改、权限变更的改动。
- 发现已上线系统存在同类漏洞，本次改动会扩大影响面。
- 需要跳过权限校验或引入临时后门。

## 交付前

- 依赖漏洞扫描无高危；有高危必须升级依赖或写清缓解措施并人签收。
- 新增的权限点已在 07 的变更清单中列出，并说明授权给哪些角色。
- 回滚方案中不包含「无法回滚的加密密钥或数据格式变更」；如果有，必须单独评估并人签收。
