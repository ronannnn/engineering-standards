# 适配：前端设计质量

03 UI/UX 阶段的「设计好不好」由人与检查清单判定，门禁只判「有没有写」。本文件给出可判定的最低要求，并说明如何接入外部设计体系。

## 最低要求（12 条，逐条可判定）

| # | 要求 | 判定方式 |
|---|---|---|
| 1 | 主操作在任何视口可见且唯一 | 截图：首屏有且只有一个主按钮 |
| 2 | 空/加载/错误/无权限状态均有具体文案与视觉 | 03 的六个状态逐个有内容，不写「有提示」 |
| 3 | 危险操作二次确认，且说明影响范围 | 弹窗含影响数量/对象与不可逆说明 |
| 4 | 键盘可完成主流程 | Tab 顺序与视觉顺序一致，焦点可见 |
| 5 | 对比度达标 | 正文与背景 ≥ 4.5:1，大字号 ≥ 3:1 |
| 6 | 表单错误定位到字段并给出修正建议 | 错误文案含「哪个字段 + 怎么改」 |
| 7 | 加载超过 1 秒有反馈，超过 3 秒说明可离开 | 骨架屏或 spinner + 文案 |
| 8 | 移动端不出现横向滚动（表格除外，且表格可横向滑动） | 375px 宽度截图核对 |
| 9 | 只用设计系统既有 token 与组件 | diff 中无新增色值/字号/圆角常量 |
| 10 | 交互元素有 hover / focus / active / disabled 四态 | 组件测试或截图核对 |
| 11 | 长文本、超长单词、空数据不破版 | 用最坏数据渲染核对 |
| 12 | 文案与界面语言一致，无占位符残留 | 全文搜索 `TODO`、`lorem`、`xxx` |

## 外部设计体系怎么接

- **impeccable**（你本地已安装的技能）：只作为「设计判断」的输入，用于确定页面模式（引导型 / 体验型 / 操作型 / 阅读型）与视觉方向。它没有许可证声明，因此**不把它的正文搬进本仓库**，只借鉴「按模式决定设计强度」的方法。
- **web-interface-guidelines**（MIT）：可以逐条吸收它的可访问性、表单、动效、排版检查项，改写成中文并注明出处后加入上表。目前上表是它的子集 + 本项目优先项。
- **项目自有设计系统**：以项目仓库里的组件库与 token 为准；上表第 9 条是硬约束。

## 在 03 阶段怎么用

1. 先按项目设计体系盘点可复用组件，再设计新页面。
2. 用上表逐条自检，把不满足的项写进 `## 视觉验收标准` 或列为已知取舍。
3. 交给 UX 角色（`org-role-ux`）与人签收；有关键页面时人必须签收。
4. 06 阶段评审时，前端相关发现按「严重/重要/轻微」分级，第 1、3、4、5 条不合格按「重要」起步。
