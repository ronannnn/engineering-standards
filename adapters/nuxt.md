# 适配：Nuxt 前端

本文件只写「本项目标准在 Nuxt 前端上怎么落地」。框架能力以项目实际安装版本为准；已安装 `nuxt-app` 技能时优先读它。

## 阶段落点

| 阶段 | Nuxt 前端特有的要求 |
|---|---|
| 01 需求分析 | 明确影响哪些页面与角色；写清移动端是否在范围内 |
| 02 技术设计 | 接口契约与后端对齐；写清状态管理（页面状态 / store）与数据获取方式 |
| 03 UI/UX 设计 | 必须有；页面清单标出关键页面；六个交互状态逐个写 |
| 04 开发计划 | 每个任务落到具体 `.vue` / `composables` 文件；页面与组件分开拆 |
| 05 编码实现 | 测试命令用 `pnpm`/`vitest`；组件测试覆盖六个状态 |
| 06 测试与评审 | 关键页面走 e2e；补可访问性检查 |
| 07 交付 | 写清前端版本与后端版本的兼容关系 |

## 命令约定（按项目实际调整）

```bash
pnpm install
pnpm build
pnpm test                     # vitest 单元/组件
pnpm test -- <文件或用例名>    # 局部证据（推荐用于 05）
pnpm test:e2e                 # Playwright
pnpm lint
pnpm typecheck
```

## 设计检查点

- **组件复用**：先查 `@nuxt/ui` 与 `v-nuxt-ui` 提供的组件；确实要新增时才自造，并在 03 里登记归属目录。
- **设计 token**：颜色、间距、圆角只用既有 token；不新增色值。
- **数据获取**：`useAsyncData` / `useFetch` 的 key 与缓存策略在设计里写明，避免重复请求。
- **状态**：区分「页面内状态」与「跨页状态」；跨页才进 store，且写清失效时机。
- **路由与权限**：中间件与权限判断写清；无权限时页面表现必须出现在 03 的六个状态里。
- **SSR 安全**：不在服务端渲染阶段读取仅客户端可用的存储。

## 测试检查点

- 组件测试覆盖：空、加载、错误、无权限、成功、危险操作确认。
- 表单测试覆盖：必填校验、边界长度、提交失败重试。
- 关键页面 e2e 至少覆盖主流程一次，并断言关键文案与 URL。
- 可访问性：至少检查键盘可达与对比度；有工具就接（如 axe）。

## 适配提示

- 已安装 `nuxt-app` 技能时，在 03/05 阶段读取其组件与表单约定，保持与既有页面一致。
- 项目使用 `@nuxt/ui` v4 时，注意组件 props 以实际安装版本为准，不照抄旧版本文档。
