# 适配：Go 后端（go-infra）

本文件只写「本项目标准在 Go 后端上怎么落地」，不重复框架文档。框架能力以项目实际安装版本为准；已安装 `go-infra` 技能时优先读它。

## 阶段落点

| 阶段 | Go 后端特有的要求 |
|---|---|
| 01 需求分析 | NFR 必须给 P95、QPS、数据量级；涉及表的写清预计行数与增长 |
| 02 技术设计 | 接口契约用真实路由与方法；数据模型与迁移写到表/字段/索引级；错误码与错误类型单列 |
| 03 UI/UX | 一般整份不适用（除非有后端渲染页面） |
| 04 开发计划 | 每个任务落到具体 `.go` 文件；迁移单独成任务 |
| 05 编码实现 | 测试命令用 `go test`；表驱动测试；错误用类型化错误而非字符串匹配 |
| 06 测试与评审 | 至少覆盖：参数化查询、越权、错误分支、迁移回滚 |
| 07 交付 | 写清迁移执行顺序、回滚顺序、健康检查接口 |

## 命令约定（按项目实际调整）

```bash
go build ./...                                   # 构建
go test ./...                                    # 全量测试
go test ./internal/<pkg>/... -run TestXxx -v     # 局部证据（推荐用于 05）
go vet ./...                                     # 静态检查
golangci-lint run                                # 若项目已配置
go test ./... -coverprofile=cover.out            # 覆盖率
```

## 设计检查点

- **接口分层**：handler → service → repository，禁止 handler 直接操作数据库。
- **事务边界**：批量写入必须在一个事务内，失败整体回滚；事务内不调用外部服务。
- **幂等**：重复提交的写接口要有幂等键（唯一索引或指纹），并在设计中写明冲突返回码。
- **错误处理**：预期失败用类型化错误与稳定判别码；不要靠解析错误消息做分支；用户可见错误与内部错误分离。
- **迁移**：优先使用项目既有迁移工具；每个迁移要有 up/down；大表变更先加可空列再回填。
- **配置**：新增配置项给默认值并写进配置文档；禁止把可变参数硬编码。

## 测试检查点

- 表驱动测试覆盖边界：空值、零值、超大值、并发。
- 每个接口至少一个失败分支用例（400/403/404/409/422）。
- 批量接口必须有幂等用例与事务回滚用例。
- 断言外部结果（数据库行数、返回体、状态码），不依赖日志文本。

## 适配提示

- 已安装 `go-infra` 技能时，在 02/05 阶段读取它的 CRUD、动态查询、错误处理约定，保持与既有代码一致。
- 项目若使用 Gin/Echo/Fiber，按其中间件与错误渲染方式调整，不要为符合本文改动框架。
