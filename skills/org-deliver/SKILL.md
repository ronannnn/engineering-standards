# 07 集成与交付（org-deliver）

## 何时使用

- `06-test-report.md` 结论为「可发布」且 `06-review-report.md` 结论为「可合并」。
- 准备开 PR、合并、部署或发布时。

## 输入

| 输入 | 要求 |
|---|---|
| 06 两份报告 | 必须 `已冻结`，否则不得进入交付 |
| CI 结果 | 单元、构建、静态检查、安全扫描、标准门禁 |
| 部署环境 | 目标环境、权限、时间窗口、观察方式 |

## 产出

`07-delivery.md`，编号 `DLV-0001`，必须人签收。

## 步骤

1. **汇总变更清单。** 逐条写功能、修复、配置、数据、依赖变更；不写「若干优化」。数据与依赖变更必须单独列出，它们决定回滚难度。
2. **记录 CI 结果。** 表格每行：检查项、结果、证据（日志或链接）。必须包含一行「标准门禁」，未通过不得交付。
3. **写部署方案。** 步骤、负责人、时间窗口、前置依赖（迁移、配置、开关）。
4. **写回滚方案。** 触发条件、步骤、数据回滚是否可逆、预估耗时。回滚方案写不出来，说明这次交付不该上线。
5. **写健康检查与监控。** 健康检查接口与期望状态、关键指标与告警阈值、观察窗口、出问题时看哪里。
6. **声明 AI 参与度。** 五个环节（需求拆解、方案设计、验收测试、技术实现、评审处理）各选一个等级，并写一句「人做了什么、AI 做了什么」。等级从「人工独立」到「模型自主」，按实际填，不要美化。
7. **交人签收。** 把 `状态` 改 `待签收`，由验收人确认；对方填 `签收`、`签收时间`、`确认时间`，并把 `状态` 改 `已冻结`。

## 冻结

- 07 必须人签收，不能用 `机器门禁`。
- 部署后若结果与方案不符，回到本阶段更新「部署结果」，`修订` +1，重新签收。

## 门禁

```bash
python3 gates/run.py docs/engineering/<slug> --stage 07
```

常见失败：CI 表缺「标准门禁」行或该行非通过、回滚方案缺触发条件/步骤/耗时、AI 参与度缺环节或等级非法、交付确认缺验收人或日期、06 结论不满足。

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 没有回滚方案就上线 | 出事只能硬扛 | 先写回滚，再排上线时间 |
| 监控只写「看日志」 | 出事定位慢 | 写指标、阈值、观察窗口 |
| AI 参与度全填「模型自主」 | 数据失真，复盘无依据 | 按事实填，允许「人工把关」 |
| 直接合并未签收的交付记录 | 门禁会红 | 走完签收再开 PR |
| 把遗留问题藏起来 | 后续需求重复入坑 | 写进「遗留与后续」 |

## 交接

07 冻结后创建 PR（用仓库的 PR 模板，含 AI 参与度声明），合并后进入 08 复盘。
