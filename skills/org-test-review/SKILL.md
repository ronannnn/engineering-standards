# 06 测试与评审（org-test-review）

## 何时使用

- `05-implementation.md` 已冻结，需要独立验证与评审时。
- 修复评审意见后重新验证时（重新跑受影响用例，并在报告里更新结果）。

## 输入

| 输入 | 要求 |
|---|---|
| `01-requirements.md` | 验收标准表（矩阵审计的唯一依据） |
| `05-implementation.md` | 证据台账、变更文件、未完成项 |
| 真实环境 | 能跑测试的运行时；必要时预发环境与真实依赖 |

## 产出

- `06-test-report.md`（`TST-0001`，QA 写）
- `06-review-report.md`（`REV-0001`，评审写）

## 步骤（测试报告）

1. **先建矩阵。** 把 01 的每条 AC 复制进 `## 矩阵审计`，逐条找「哪个用例真的跑过」；跳过（skip）不算覆盖。
2. **跑用例并记录。** `## 用例与结果` 每行：编号、对应 AC、类型、命令、结果、证据。结果只能是 通过/失败。
3. **失败必须复验。** 有失败用例时，`## 失败与修复` 每行都要有复验结果=通过；否则报结论只能是「不可发布」。
4. **验证外部世界，不是自述。** 断言要重跑命令、重读文件、查数据库、看接口返回，而不是相信实现者的说明。
5. **写清盲区。** `## 未覆盖与风险` 写跳过原因与可能影响；覆盖率不适用时给理由。

## 步骤（评审报告）

1. **不信报告，只看 diff。** 先拿到基线与 head，再逐文件读改动与上下文；实现者的说明只是线索。
2. **先判规格符合性。** 逐条对 01/02/04：符合 / 不符合 / 无法判定；「无法判定」必须写清缺什么证据。
3. **分级列发现。** 严重（必须修）/ 重要（应修）/ 轻微（可延后），每条带 `file:line`、影响、修复建议。没有就写「无」，不要省略标题。
4. **安全与兼容单列。** 至少覆盖注入、越权、敏感信息、输入校验；有 schema/接口变更时核对迁移与回滚。
5. **写「分歧记录」。** 你主动决定不评审或不判定的部分写在这里，让执行者必须裁定，不要静默放过。
6. **给结论。** 可合并 / 需修改；有严重或重要发现、或规格不符合时不得判可合并。

## 风险升级

出现以下情况必须停下找人，不得自行放行：

- 涉及资金、权限、数据删除的改动，且测试未能覆盖。
- 失败用例无法在本地复现，且 CI 也不稳定。
- 评审发现「实现与需求方向不一致」，需要产品决策。

## 冻结

两份报告都由 agent 在门禁全绿后置 `已冻结`、`签收: 机器门禁`；**风险升级时改为 `待签收`，由人决定**。

## 门禁

```bash
python3 gates/run.py docs/engineering/<slug> --stage 06
```

常见失败：矩阵审计缺 AC 或标「否」、有失败用例却判可发布、评审有严重发现却判可合并、发现缺 file:line、安全性检查缺注入或越权。

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 用「单元全绿」代替验收 | 真实路径没跑，线上翻车 | 矩阵审计逐条对 AC |
| 重跑一次偶发失败就算过 | 掩盖不稳定 | 记录原因，修根因或标注风险升级 |
| 评审先看实现说明 | 被叙述带偏 | 只看 diff 与命令输出 |
| 问题降级以免阻塞 | 技术债变成线上事故 | 按影响定级，不用协商定级 |
| 矩阵审计漏 AC | 门禁与评审都过不去 | 从 01 复制，逐条勾 |

## 交接

06 冻结后交给产品经理与开发进入 07；有「需修改」或「不可发布」时回到 05 修复，不要进入 07。

## 本次契约补充

矩阵逐条关联实际用例编号、通过结果和对应 AC，不能仅勾“是”。用例编号和矩阵 AC 不得重复，引用失配需修正。测试及评审结论只选一个值；规格无法判定不得判可合并。披露独立会话/人员评审还是同一执行者自审，区分阻塞、建议和偏好。先跑工具验证，再复核语义；未执行的真实 Agent 试跑单列。

评审协作记录时，核对实际变更与授权范围、后续消息归属、人工暂停及恢复依据；区分待评审和已完成。没有相关操作就说明不涉及，不要求空造记录。连续协作的真实试跑按 [补充场景](../../policies/workflow-evaluation.md) 执行；门禁通过不能证明运行权限或多会话行为已验证。

## 模块与子模块

同路径核对模块需求、设计、任务和证据；根 06 汇总限定 AC/用例并保留跨模块集成验证。根 07 的模块报告修订必须匹配。组织、引用、命令与迁移见 [模块资料规则](../../policies/modular-artifacts.md)。
