# 03 UI/UX 设计（org-ui-design）

## 何时使用

- 需求包含页面、组件、交互或视觉改动时。
- 纯后端/纯脚本需求：不调用本技能，直接把 03 标为整份不适用（frontmatter `不适用: <理由>`）并冻结。

## 输入

| 输入 | 要求 |
|---|---|
| `02-design.md` | 必须 `已冻结`；接口能力决定了页面能做什么 |
| 现有设计系统 | 组件库、token、既有页面；先看再设计 |
| 品牌与可访问性约束 | 对比度要求、平台规范、国际化 |

## 产出

`03-ui-design.md`，编号 `UIX-0001`。

## 步骤

1. **先盘点可复用组件。** 打开项目组件库（如 Nuxt 项目里的 `@nuxt/ui` 与 `v-nuxt-ui` 封装），页面清单里逐行写清复用哪个组件；确实要新增的写 `新增：<组件名>` 并给出归属目录。
2. **标出关键页面。** `## 页面清单` 的「关键」列只能是 是/否；任意一个「是」→ 本阶段必须人签收。判定标准：改错会造成资金、权限、数据或主流程中断的页面算关键。
3. **写关键流程。** 编号步骤覆盖：进入、操作、成功、失败、退出。不要用「见截图」代替文字。
4. **状态全覆盖。** `## 交互与状态` 六个标签（空、加载、错误、无权限、成功、危险操作确认）逐个写具体表现，不能只写「有对应提示」。
5. **写可访问性。** 至少覆盖键盘可达与对比度；有表格/弹窗时补语义与焦点管理。
6. **写可判定的视觉验收标准。** 每行：编号、页面、判定标准、检查方式、可自动化。「按钮用 primary-600」可以，「看起来舒服」不可以。
7. **交人签收（条件触发）。** 有关键页面：改 `待签收` 由人冻结；无关键页面：直接 `已冻结`、`签收: 机器门禁`。

## 冻结

- 有关键页面 → 必须人签收。
- 无界面需求 → 整份 `不适用`，但仍要冻结后才进入 04。

## 门禁

```bash
python3 gates/run.py docs/engineering/<slug> --stage 03
```

常见失败：页面清单缺「关键」或「复用组件」列、六个状态标签缺项、可访问性缺键盘或对比度、视觉验收标准为空、有关键页面却用机器签收。

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 每个页面都标「关键」 | 人被迫审所有页面，关键性失效 | 只标会出事的那几个 |
| 自造样式不写复用 | 设计系统被稀释，前端返工 | 复用组件与 token，新增要说明理由 |
| 只画正常流程 | 空/错/无权限状态上线才补 | 六个状态一起设计 |
| 验收标准写成「美观」 | 无法验收，评审各说各话 | 用 token、尺寸、文案、断言描述 |
| 后端需求硬写 UI 文档 | 制造无意义文档 | 整份不适用 + 理由 |

## 交接

冻结后把 `03-ui-design.md`、组件与 token 清单交给开发（`org-role-dev`），由它进入 04 拆任务。
